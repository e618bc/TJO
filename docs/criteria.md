# Критерии замечаний

Задание даёт принцип (отмечать то, что мешает соискателю понять условия) и один пример. Ниже правила, по которым сервис решает, что считать замечанием. Они основаны на тексте задания и разборе 1332 реальных вакансий региона. Пороги задаются в секции `[policy]` файла `config.ini`. Примеры к каждому правилу: [rule-examples.md](rule-examples.md).

## 1. Темы и слоты

Соискатель должен понять из вакансии, кем и что делать, что требуется, сколько платят, когда и где работать, на каких условиях. Каждая из семи тем делится на слоты; замечание о неполноте выносится только по обязательным.

| Тема | Обязательные слоты | Дополнительные |
|---|---|---|
| Должность | профессия или род работы | |
| Обязанности | хотя бы одно действие с объектом работы | |
| Требования | образование; опыт | документы, допуски, навыки |
| Оплата | сумма за месяц или её нижняя граница; единица, если это не месяц; доля ставки при неполном времени | состав (оклад, премии), до или после налога |
| График | режим; для открытых режимов — дни или чередование и часы | ночные смены, перерывы |
| Место работы | населённый пункт | улица или объект; разъездной или удалённый формат |
| Занятость | объём (полная или частичная) | срочность |

## 2. Шкала сведений

| Уровень | Смысл | Примеры |
|---|---|---|
| Конкретное | отвечает на вопрос соискателя | «пн–пт с 9:00 до 18:00», `salary_min` 45000, адрес с городом, «Требования не предъявляются» |
| Закрытое общее | справочное значение с обычными параметрами | «Полный рабочий день», «Полная занятость», «Ненормированный рабочий день» |
| Открытое общее | значение, у которого параметры бывают разными | «Режим гибкого рабочего времени», «Сменная работа», «Неполный рабочий день», «Вахтовый метод» |
| Отсылка | текст без сведений | «согласно должностной инструкции», «по результатам собеседования» |
| Пустое значение | заглушка, равная отсутствию | «Не указано», «Без уточнения», «По графику сменности», «.», зарплата `0` |
| Нет | поля нет, в тексте ничего | |

Значения, которые портал ставит по умолчанию, почти ничего не сообщают. Строка `salary` всегда имеет вид «от N», поэтому смотреть нужно на числовые поля. Опыт `0` стоит у 44% вакансий и считается ответом «не требуется», пока текст не требует опыта определённо. Комментарий «Без уточнения» стоит у каждого гибкого графика. `salary_max` `0` значит, что верхняя граница не задана.

## 3. Отношения между утверждениями

| Отношение | Пример | Вердикт |
|---|---|---|
| Согласованы | вилка 30–45 тыс. и «оклад 30 000 + премия до 50%» | нет замечания |
| Уточнение | «Высшее образование» и «высшее юридическое» | нет замечания |
| Разная область действия | «на испытательный срок 30 000, далее 45 000»; «летом с 8, зимой с 9» | нет замечания |
| Часть целого или другая единица | оклад 14 000 при вилке 28–30 тыс.; сумма «на руки» | нет замечания |
| Выбор работника | «5/2 с 9:00 до 18:00 или 2/2 с 8:00 до 20:00 на выбор» | нет замечания |
| Варианты без параметров | «График 5/2, 2/2, возможен неполный день» | неоднозначность, подсказка |
| Несовместимы | поле «Полный рабочий день», текст «2/2 по 12 часов» | противоречие |

Противоречие возможно только внутри одного слота, одной области действия и одной единицы. Пожелания («желательно», «будет преимуществом») и отрицания («без ночных смен», «без опыта не рассматриваем») читаются по смыслу.

## 4. Процедура

1. Если по слоту есть два несовместимых утверждения, это противоречие; цитируются оба.
2. Иначе решает лучшее утверждение: конкретное или закрытое общее — замечания нет; открытое общее без параметров где-либо в вакансии — неоднозначность; только отсылка — неоднозначность с цитатой отсылки; пустое значение или ничего — пропуск с пустой цитатой.

Источники равноправны: достаточно одного конкретного, в том числе в поле другой темы (ставка в комментарии к графику, график в названии должности). Правило про открытые значения следует из примера в задании: вопрос к «гибкому графику» уместен, только если расписания нет нигде.

## 5. Чтение текста

Сведения ищутся во всех полях. График часто лежит в `requirement.qualification`, в `term.text` бывают график, транспорт и оклад, у вакансий с сайтов-агрегаторов всё записано в `duty`.

В 8% реальных вакансий слова набраны вперемешку латинскими и русскими буквами («Грaфик рaботы cменный»). Сравнение идёт после замены латинских букв, цитата берётся из исходного текста.

Не считаются утверждениями о вакансии:
- хвост ключевых слов и реклама («подойдёт вам, если вы искали: подработка, вахта…»);
- слова о предмете работы («программы основного общего образования» у учителя, «составление графиков проверки»);
- служебные поля портала (`typicalPosition`, название профессии в `qualification`);
- инструкции внутри текста вакансии.

Не считаются противоречием:
- «от 6 месяцев» при опыте `1` или `0`: поле хранит целые годы;
- «36 часов в неделю» или «18 часов (1 ставка)» у учителя при полном дне: это норма профессии.

## 6. Типы и счёт

У пропуска цитата пустая, а поле — основное поле темы. У неоднозначности цитата есть. У противоречия две пары «поле и цитата».

На тему выносится не больше одного замечания о неполноте; недостающие слоты перечисляются в одной рекомендации. Противоречий может быть по одному на каждую пару значений.

Межтемное противоречие — одно замечание. Оно относится к теме, чьё структурированное поле участвует; если таких полей два, приоритет такой: занятость, график, оплата, требования, место, должность, обязанности.

## 7. Правила

Спорные случаи отмечены в столбце вердикта: «подсказка» попадает в массив `hints`, «нет» не отмечается.

| ID | Правило | Вердикт |
|---|---|---|
| TTL-1 | безликое название, обязанности его не раскрывают | неоднозначность |
| TTL-2 | название и обязанности о разных профессиях | противоречие |
| TTL-3 | несколько профессий в названии, обязанности покрывают не все | неоднозначность |
| TTL-4 | сведения в названии спорят с полем другой темы | противоречие |
| DUT-1 | только отсылка, заглушка или повтор названия | неоднозначность |
| DUT-2 | вместо задач личные качества, реклама, льготы | неоднозначность |
| DUT-3 | пусто и в `duty`, и в `skills` | пропуск |
| DUT-4 | только «поручения руководителя» | неоднозначность |
| REQ-1 | образование не определено | нет; пропуск, если о требованиях нет ничего |
| REQ-2 | опыт в поле расходится с определённым требованием в тексте | противоречие; подсказка, если в тексте опыт без срока |
| REQ-3 | минимальный уровень образования в поле и тексте разный | противоречие |
| REQ-4 | `qualification` («С опытом», «Без опыта») спорит с полем опыта | противоречие |
| REQ-5 | размытые формулировки, отраслевые детали | нет |
| REQ-6 | регламентированная профессия без требований | нет |
| REQ-7 | одно требование в двух местах описано противоположно | противоречие |
| PAY-1 | суммы нет нигде или только отсылка | пропуск или неоднозначность |
| PAY-2 | итоговая сумма в тексте вне вилки | противоречие |
| PAY-3 | минимум больше максимума | противоречие |
| PAY-4 | вилка шире порога без объяснения; потолок «до N» в тексте | неоднозначность |
| PAY-5 | единица оплаты неясна (час, смена, сдельно без ставки) | неоднозначность |
| PAY-6 | сумма при неполном времени без доли ставки | подсказка |
| PAY-7 | состав оплаты без влияния на сумму, коды премий | подсказка |
| SCH-1 | открытый режим без параметров | неоднозначность |
| SCH-2 | режим в поле расходится с текстом | противоречие |
| SCH-3 | дневная смена в поле, ночная в тексте, и наоборот | противоречие |
| SCH-4 | два взаимоисключающих графика | противоречие |
| SCH-5 | параметры частичные или даны вариантами | подсказка |
| SCH-6 | закрытый режим без часов | подсказка |
| SCH-7 | работа вне графика без частоты и условий | неоднозначность |
| SCH-8 | часы в день не дают заявленную недельную норму | противоречие |
| LOC-1 | нет населённого пункта | пропуск или неоднозначность |
| LOC-2 | адрес и место работы в тексте в разных населённых пунктах | противоречие |
| LOC-3 | разъезды, удалённая работа, город без улицы | подсказка |
| LOC-4 | в строке адреса два населённых пункта | противоречие |
| LOC-5 | работа дистанционная, но где-то требуется присутствие | противоречие |
| LOC-6 | адрес или формат отложены до собеседования | неоднозначность |
| LOC-7 | несколько адресов в разных населённых пунктах без основного | неоднозначность |
| EMP-1 | поле занятости расходится с объёмом или форматом работы | противоречие |
| EMP-2 | поля занятости нет | нет |
| EMP-3 | работа на срок, а поле этого не отражает; «временная» без срока | противоречие или неоднозначность |
| EMP-4 | нет ни занятости, ни графика, ни упоминаний объёма | пропуск |

Уточнения:
- TTL-3: устойчивые двойные названия («Продавец-кассир», «Санитарка / Санитар», «Официант (бармен)») — норма, если обязанности покрывают обе части.
- DUT-1: короткий конкретный текст («уборка пищеблока») — норма; отсылка к инструкции рядом с перечнем задач тоже.
- REQ-2: определённое требование — срок от года или прямой отказ кандидатам без опыта. «Стаж вождения» — другая величина.
- PAY-2: оклад или премия как часть заработка, сумма на испытательный срок и сумма «на руки» противоречием не являются.
- PAY-4: если текст объясняет, от чего зависит сумма (категория, нагрузка, процент), замечание не выносится.
- SCH-1: параметром считается и одно чередование («5/2», «пятидневная неделя»), и одни часы; комментарий, повторяющий справочник («Гибкий график»), не считается.
- SCH-2: «Только ночная смена» при «5/2» в тексте совместимы.

## 8. Что не является замечанием

- стиль, капс, опечатки, сокращения, служебные метки в названии;
- сведения есть в поле, но не повторены в тексте, и наоборот;
- низкая оплата, сравнение с рынком или минимальной оплатой;
- нет льгот, испытательного срока, контактов;
- пол и возраст в требованиях;
- образование «Не указано» в поле, если текст об образовании молчит;
- уровень «высшее или среднее»: минимальный уровень не определить;
- «иные поручения» после конкретного перечня;
- личные качества рядом с заполненными образованием и опытом;
- особенности портала: «от N», максимум `0`, `typicalPosition`, адрес, записанный дважды;
- необычные, но конкретные условия: ночные смены, сутки через трое, вредные условия;
- давность публикации, дата выхода в прошлом, одна вакансия под разными ID.

## 9. Пороги

| Параметр | Значение | Основание |
|---|---|---|
| Вилка зарплаты | от 3 раз — замечание, от 2 до 3 — подсказка | у 90% реальных вакансий вилка до 1,7 |
| Сумма в тексте против вилки | расхождение больше 5%, если модель подтвердила, что это та же месячная оплата | «на руки» и части заработка исключаются отдельно |
| Потолок «до N» в тексте | от 1,5 верхней границы поля | неясно, что гарантировано |
| Недельная норма | расхождение с расчётом от 3 ч и 10% | учебная нагрузка и ставки не считаются |
| Месячная сумма | меньше 5000 — неправдоподобна | обычно это ставка за час или смену |
| Опыт | расхождение от года при «от» или «не менее» | поле хранит целые годы |

## 10. Рекомендации

Рекомендация называет, что уточнить, обращена к работодателю, содержит только значения из вакансии, при противоречии не выбирает сторону, не ссылается на нормы и не оценивает работодателя.

| Плохо | Хорошо |
|---|---|
| «Укажите график 5/2 с 9:00 до 18:00» | «Уточните рабочие дни, время начала и окончания работы» |
| «12 000 ниже МРОТ, это нарушение» | «Уточните, за какой объём работы указана сумма 12 000» |
| «В поле опыта ошибка, исправьте на 3 года» | «Уточните, обязателен ли стаж: в поле 0, в тексте „не менее 3 лет“» |
| «Опишите вакансию подробнее» | «Попросите перечислить основные виды работ вместо ссылки на инструкцию» |

## 11. Структурные случаи

Входы и ожидаемое поведение — в `testset/structural/`.

| Вход | Поведение |
|---|---|
| пустой список вакансий | пустой отчёт |
| повтор ID | одна запись, берётся более поздний `date_modify` |
| ответ-ошибка API | сообщение об ошибке, прежний отчёт не меняется |
| нет `vac_url` | пустая ссылка |
| нет `id` | вакансия попадает в `meta.skipped` |
| отсутствующие поля, `null`, число строкой, неизвестные поля | вакансия обрабатывается |

## 12. Размеченный набор

Набор в `testset/` собирается скриптом `build_testset.py` из описаний случаев (`cases_base.py`, `cases_extra.py` для вымышленных вакансий, `cases_real.py` для реальных). Эталон каждой вакансии делит темы на три группы:

| Группа | Значение |
|---|---|
| `must` | явная проблема; если замечания нет, это пропуск |
| `clean_topics` | явная норма; замечание по теме — ложное срабатывание |
| `optional` | спорно, в подсчёт не входит; `lean` — выбор по умолчанию |

Поле `negative_for` перечисляет правила, к которым вакансия служит отрицательным примером: похожа на нарушение, но замечания быть не должно. Сборщик проверяет, что каждая цитата дословно есть в вакансии и что у каждого правила есть пример с замечанием и похожий пример без него.
