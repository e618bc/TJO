Прозрачная вакансия

Тестовое задание для команд

Разработайте прототип, который автоматически получает вакансии Калининградской области с портала «Работа в России» и формирует отчёт о том, насколько понятно описаны условия работы. Отчёт поможет редактору вакансии подготовить конкретные уточнения для работодателя.

# Источник данных и запуск

API «Работа в России» для региона 39 <http://opendata.trudvsem.ru/api/v1/vacancies/region/39>

[<u>Документация API «Работа в России»</u>](https://trudvsem.ru/opendata/api)

- Рабочий режим. Сервис загружает вакансии через API региона 39, обрабатывает их и сохраняет отчёт по расписанию без ручного копирования текста. Предусмотрите ручной запуск того же процесса для проверки. Настраиваются URL источника, расписание и максимальное число вакансий.

- Проверочный режим. Тот же анализатор принимает локальный JSON в формате ответов API и формирует отчёт по всем переданным вакансиям без обращения к порталу. Команда организаторов выдаст учебный пример вместе с заданием. Для оценки жюри использует отдельный набор.

- Обработайте хотя бы две страницы, если лимит и объём данных позволяют. Повторный запуск на неизменных данных сохраняет один результат на ID вакансии в текущем отчёте. При недоступности API сообщите об ошибке и сохраните последний успешный отчёт, если он есть.

# Что проверять в вакансии

Оцените название должности, обязанности, требования, оплату, график, место работы и тип занятости. Учитывайте и описание, и структурированные поля API. Если поле содержит конкретные сведения, отсутствие их повторения в описании само по себе не считается проблемой.

Отмечайте пропуски, неоднозначности и противоречия, которые мешают соискателю понять условия. Например, при формулировке «гибкий график» вопрос о днях и сменах уместен, если конкретного расписания нигде нет. Рекомендация должна подсказывать, что именно уточнить, без вымышленных фактов и выводов о нарушении закона.

Заказчик задачи ориентируется на государственные и муниципальные организации. Для MVP обрабатывайте вакансии региона, которые передаёт источник. Определять форму собственности работодателя не требуется.

# Формат отчёта

Сохраните отчёт в JSON. Для каждой входной вакансии верните отдельный объект с её ID, ссылкой на карточку при наличии и массивом замечаний. Если замечаний нет, верните пустой массив. Команда может использовать свои имена полей, если опишет их в README.

В каждом замечании укажите тему, поле источника, цитату или значение из него, суть проблемы и конкретную рекомендацию. Для пропуска укажите поле, оставьте цитату пустой и объясните, каких сведений не хватает. Для противоречия приведите оба исходных значения.

# Использование ИИ

В базовом сценарии ИИ должен выполнять часть обработки данных, которая влияет на отчёт. Например, модель может выявлять неоднозначные формулировки или предлагать уточнения по конкретным полям вакансии. Команда сама выбирает модель и провайдера. Можно использовать локальную модель.

# Дополнительный сценарий

По желанию предложите и покажите свой сценарий на данных API региона 39. Например, сервис может подготовить черновик резюме под выбранную вакансию на основе резюме, которое предоставил соискатель. Для демонстрации используйте вымышленные или обезличенные резюме. Опыт, навыки и образование берите из исходного резюме.

Кратко опишите в README, кому помогает ваш сценарий, какие данные API он использует и какой результат выдаёт. Базовый отчёт о вакансиях обязателен для всех команд.

# Материалы для сдачи

- Публичный Git-репозиторий и SHA коммита, который отправляете на оценку. В репозитории разместите исходники, конфигурацию автоматизации, README и пример отчёта на учебных данных.

- README с зависимостями, настройками, командами запуска и проверок, форматом отчёта и вкладом участников. Укажите модель, провайдера или способ локального запуска и шаг, на котором используется ИИ. Дайте жюри способ запустить проверочный режим с ИИ без покупки аккаунта. Храните ключи вне репозитория.

- Видео до 3 минут. Покажите, как сервис получает данные, где применяет ИИ и какой результат выдаёт. Если добавили свой сценарий, кратко покажите его. Укажите в README файл или workflow, с которого начинается обработка. Видео должно открываться у жюри без запроса доступа.

Выбор стека свободный. Можно сочетать ИИ с правилами и no-code. Для n8n приложите импортируемый JSON workflow, версию n8n и инструкцию. Для другого стека приложите сценарий и конфигурацию расписания. Интерфейс и публичный деплой по желанию.
