# TJO

Сервис загружает вакансии Калининградской области с портала «Работа в России» и строит JSON-отчёт для редактора: что в условиях работы непонятно, где это написано и что уточнить у работодателя.

Решение задания «Прозрачная вакансия» онлайн-отбора хакатона КАНТКОД.

## Запуск

Нужен Python 3.9 или новее, сторонних библиотек нет.

Основной режим использует модель Gemma 4 на Cloudflare Workers AI. Аккаунт бесплатный, бесплатной дневной квоты хватает примерно на 400 вакансий.

1. На cloudflare.com откройте Workers AI → Use REST API → Create a Workers AI API Token.
2. Скопируйте `.env.example` в `.env` и впишите Account ID и токен.
3. Запустите:

```bash
python3 -m vacancy_clarity doctor
python3 -m vacancy_clarity check examples/kantkod_sample_vacancies.json --print
```

`doctor` проверяет, что модель отвечает. `check` строит отчёт `data/check_report.json` (другой путь — `--out`); с `--print` замечания выводятся и в терминал.

На вход `check` подходит ответ API, список ответов, список вакансий или папка с файлами `*.json`. К порталу проверочный режим не обращается, лимит на число вакансий не применяет.

### Другие способы

| Способ | Как включить | Учебный пример |
|---|---|---|
| Локальная модель без аккаунта, ~4 ГБ памяти, без видеокарты | `ollama pull qwen3.5:4b`, затем `--engine ollama` | 9 из 10 |
| Та же Gemma 4 на своём сервере, ~16–18 ГБ памяти | `ollama pull gemma4:26b-a4b`, затем `--engine ollama` с `VC_OLLAMA_URL` и `VC_OLLAMA_MODEL=gemma4:26b-a4b` | не измерялось |
| Любой OpenAI-совместимый сервис | `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` в `.env`, затем `--engine openai` | зависит от модели |
| Модели решений Clef на Cloudflare | `--engine clef` или `--engine clef-flash` | 9 из 10 |
| Без ИИ | `--no-ai` | 3 из 10 |

Для сравнения: основной режим находит все 10 обязательных замечаний учебного примера. Локальная модель работает на процессоре 10–25 секунд на вакансию и занимает половину ядер. По умолчанию (`engine = auto`) сервис пробует Cloudflare, затем OpenAI-совместимый сервис, если он задан, затем локальную модель.

## Рабочий режим

| Команда | Что делает |
|---|---|
| `python3 -m vacancy_clarity run` | загружает вакансии через API (по умолчанию 200, две страницы) и пишет `data/report.json` с копией в `data/history/` |
| `python3 -m vacancy_clarity schedule` | запускает `run` по расписанию из `config.ini` |
| `python3 -m vacancy_clarity eval ОТЧЁТ КЛЮЧ` | сверяет отчёт с ключом ответов |

Если API недоступен, вернул ошибку или пустой ответ, сервис сообщает об этом, завершается с кодом 1 и оставляет последний успешный отчёт. Каждый отчёт содержит одну запись на ID вакансии. Если модель недоступна, вакансия всё равно попадает в отчёт с замечаниями, которые код находит сам, а причина записывается в `ai.status`.

Обработка начинается в `cmd_run` (`vacancy_clarity/cli.py`) и проходит через `analyze` (`vacancy_clarity/pipeline.py`). Для запуска по расписанию вне `schedule` в `deploy/` лежат юнит systemd, строка для cron и `docker-compose.yml` вместе с Ollama.

## Настройки

Настройки — в `config.ini` (образец с пояснениями: `config.example.ini`), ключи — в `.env`. Основные параметры можно задать и переменными окружения:

| Параметр | По умолчанию | Переменная |
|---|---|---|
| `source.url` | `http://opendata.trudvsem.ru/api/v1/vacancies/region/39` | `VC_SOURCE_URL` |
| `source.max_vacancies` | 200 | `VC_MAX_VACANCIES` |
| `schedule.mode`, `interval_minutes`, `daily_at` | каждые 360 минут | `VC_SCHEDULE_MODE`, `VC_INTERVAL_MINUTES`, `VC_DAILY_AT` |
| `ai.engine` | `auto` | `VC_AI_ENGINE` |
| `ai.cloudflare_model` | `@cf/google/gemma-4-26b-a4b-it` | `VC_CLOUDFLARE_MODEL` |
| `ai.ollama_url`, `ai.ollama_model` | `http://127.0.0.1:11434`, `qwen3.5:4b` | `VC_OLLAMA_URL`, `VC_OLLAMA_MODEL` |

## Формат отчёта

```json
{
  "meta": {"generated_at": "…", "source": {…}, "vacancies_in_report": 10, "issues_total": 10, "ai": {…}},
  "vacancies": [
    {
      "id": "DEMO-39-003",
      "url": "",
      "job_name": "Младший аналитик данных",
      "issues": [
        {
          "topic": "requirements",
          "type": "contradiction",
          "rule": "REQ-2",
          "field": "requirement.experience",
          "quote": "0",
          "field_2": "requirement.qualification",
          "quote_2": "Требуется не менее 5 лет опыта работы аналитиком данных.",
          "problem": "В поле опыта указано 0 лет, а в тексте: «Требуется не менее 5 лет опыта работы аналитиком данных».",
          "recommendation": "Уточните, какой опыт работы обязателен, и приведите поле опыта и текст к одному значению.",
          "evidence": {"exp_text": "y3plus"}
        }
      ],
      "hints": [],
      "ai": {"status": "ok", "engine": "cloudflare", "answers": {…}}
    }
  ]
}
```

| Поле | Смысл |
|---|---|
| `topic` | `title`, `duties`, `requirements`, `salary`, `schedule`, `location`, `employment` |
| `type` | `missing` — пропуск, `ambiguity` — неоднозначность, `contradiction` — противоречие |
| `field`, `quote` | поле источника и дословная цитата или значение; у пропуска цитата пустая |
| `field_2`, `quote_2` | второе значение, только у противоречия |
| `problem`, `recommendation` | суть проблемы и что уточнить у работодателя |
| `rule` | правило из [docs/criteria.md](docs/criteria.md) |
| `evidence` | ответы модели, на которых основано замечание |

Если замечаний нет, `issues` — пустой массив. В `hints` попадают необязательные наблюдения, их отключает `[report] hints = false`. `url` — ссылка на карточку, если она есть во входных данных. Полный пример: `examples/sample_report.json`.

## Как это работает

1. Код собирает текст из всех полей вакансии, исправляет латинские буквы внутри русских слов и находит кандидатов: суммы, сроки опыта, графики, населённые пункты, отсылки «на собеседовании».
2. Модель отвечает на 4–10 вопросов с закрытыми вариантами, например «согласуются ли суммы в тексте с зарплатой в полях» или «этот населённый пункт — место работы или маршрут транспорта». Задаются только вопросы, ответ на которые может изменить отчёт.
3. Правила (`vacancy_clarity/decide.py`) выносят замечание, когда находка кода и ответ модели совпадают. Ответ «неясно» замечания не даёт.
4. Текст замечаний собирается из шаблонов с цитатами. Модель текст не пишет, поэтому выдуманных фактов и выводов о законе в отчёте нет; перед записью проверяется, что каждая цитата дословно есть в вакансии.

Ответы модели кэшируются в `.cache/ai.sqlite`: повторный запуск на тех же данных даёт тот же отчёт и не тратит квоту.

## Качество

Что считать замечанием, задание не определяет, поэтому критерии сформулированы отдельно: [docs/criteria.md](docs/criteria.md). Ключи ответов для проверки составляли внешние авторы, которые видели только текст задания и учебный пример.

| Проверка | Результат |
|---|---|
| Учебный пример, ключи трёх авторов | 10 из 10 обязательных замечаний, лишних нет |
| Контрольный набор (24 вакансии), локальная модель | 13 из 19, одно лишнее, все 9 чистых вакансий без замечаний; без ИИ — 7 из 19 |
| 100 реальных вакансий, внешний судья | из 28 замечаний 23 верных, 2 спорных, 3 неверных, выдуманных нет |

Методика и все замеры: [docs/quality.md](docs/quality.md).
